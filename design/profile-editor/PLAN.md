# แผน: ระบบแต่งโปรไฟล์ (อวตาร + ของตกแต่งซื้อด้วย coin)

สถานะ: **อนุมัติแล้ว** — อ้างอิงจากภาพออกแบบใน `design/profile-editor/stitch_just_draw_it_login_flow.zip`
(ดูเฉพาะภาพหน้าจอเพื่อเก็บแนวคิดผังหน้า/สี/ระยะห่างเท่านั้น **ห้ามเปิด/ก๊อปโค้ดจาก `code.html` ของ Stitch
เขียนใหม่ทั้งหมดด้วย React + CSS/ไอคอนพิกเซลของเกมเราเอง** — ตามที่สั่งย้ำ)

ดูสถานะความคืบหน้าแต่ละรอบที่หัวข้อ "สถานะความคืบหน้า" ท้ายไฟล์นี้ — อัปเดตทุกครั้งที่จบรอบ

## การปรับจากที่อนุมัติ (ทับแผนเดิมข้อ 1-5)

1. **เลื่อนรอบ D (อัปโหลดรูป) ไปทำทีหลังสุด** ทำ A → B → C → E → F ก่อน ถ้าทำ D วันหลังใช้ทางเลือก **(ข) fail-closed**
   (ไม่มี `GEMINI_API_KEY` หรือเรียกพัง = **ปฏิเสธการอัปโหลด** ไม่ใช่ปล่อยผ่าน เพราะรูปโปรไฟล์อยู่ถาวรกว่าโกงบนกระดาน)
2. **Solo ให้ coin ครึ่งหนึ่งของเกมปกติ เฉพาะตอน AI ทายภาพเราถูก** (ช่วง 1 "เราวาด AI ทาย" เท่านั้น)
   นับรวมใน `dailyCap` เดียวกันกับโหมดห้อง — **ไม่มี** coin จากช่วง 2 ("AI วาด เราทาย"), ไม่มี `finishGame` bonus ใน Solo
   (ผู้ใช้สั่ง "เฉพาะตอน AI ทายภาพเราถูก" ตรงๆ — ตีความว่าไม่มีทางได้ coin ทางอื่นในโหมดนี้)
3. **ตัวเลขใน `economy-rules.json`/`shop-items.json` เป็นค่าชั่วคราวทั้งหมด** รอสูตรจริงจากอาจารย์
   เขียนกำกับไว้ในเอกสาร (ไฟล์นี้ + comment ในไฟล์ json เอง) ว่ายังไม่ใช่ค่าสุดท้าย ห้ามอ้างอิงเป็นค่าทางการ
4. **ของฟรีอย่างน้อยหมวดละ 1 ชิ้นเสมอ** (กรอบ/หมวก/แว่น/คอ/พื้นหลัง) ตามความเสี่ยงข้อ 3 เดิม — กำหนดไว้ในแคตตาล็อกตั้งแต่รอบ A
   แม้ไอคอนจริงยังไม่มี (มาทำรอบ B) · **แยกตัวนับโควตา Gemini ของ "ตรวจรูปโปรไฟล์" ออกจากตัวนับของ OCR กันโกงไว้ตั้งแต่ตอนนี้**
   (รอรอบ D ค่อยใช้จริง — กันชนโควตากันเองตอนทั้งสองระบบทำงานพร้อมกัน)
5. **ข้อจำกัดที่ต้องเขียนไว้** (ไม่ใช่สิ่งที่ต้องแก้ในรอบนี้ แค่บันทึกไว้ให้รู้ตัว):
   คนคนเดียวที่มีหลายบัญชี Google ยังเปิด 2 แท็บ/2 บัญชีเข้าห้องเดียวกันแล้วทายกันเองเพื่อปั๊ม coin ได้
   (ผ่านด่าน "ห้องต้องมี ≥ 2 บัญชีจริง" เพราะนับจำนวนบัญชีไม่ใช่ตัวตนจริง) แต่ยังโดน `dailyCap` ต่อบัญชีจำกัดความเสียหายไว้

## 1. เก็บข้อมูลที่ไหน หน้าตาข้อมูลเป็นยังไง

**ที่เก็บ**: ไฟล์ใหม่ `server/wallet.js` ตามแพทเทิร์นเดียวกับ `server/leaderboard.js` เป๊ะ
- ค่าเริ่มต้น: ไฟล์ `server/data/wallet.json` (เล่นในเครื่อง)
- `UPSTASH_REDIS_REST_URL`/`TOKEN` ถูกตั้ง → ใช้ Upstash Redis คีย์ `jdi:wallet:v1` แทน (ดิสก์ Render หายตอน restart)
- โหลดทั้งก้อนใส่หน่วยความจำตอนสตาร์ท เขียนกลับเบื้องหลัง เหมือน `leaderboard.js` ทุกตัวอักษร

**กุญแจ**: **ไม่ใช้ `socket.data.accountId` ของคะแนนตรงๆ** — แฮชใหม่ namespace ของตัวเอง
`jdi:wallet-account:v1:${user.sub}` (บรรทัดเดียวกับ `index.js:120` แค่เปลี่ยน prefix) แยกระบบเศรษฐกิจออกจากคะแนนเด็ดขาด
**Guest ไม่มี accountId (`null`) เลยไม่มีกระเป๋าเงินให้ผูกได้ตั้งแต่ชั้น data model** (ตอบข้อบังคับ "Guest ไม่มี coin" ตั้งแต่ชั้นนี้)

**หน้าตาข้อมูลต่อบัญชี** (หนึ่งแถวใน `wallet.json`/Redis):
```js
{
  accountId: "a1b2c3...",
  coins: 0,
  owned: ["frame_default", "hat_default", ...],   // id ไอเทมที่ซื้อ/ปลดแล้ว (ของฟรีก็อยู่ในนี้ตั้งแต่สร้างบัญชี)
  equipped: { frame: "frame_default", hat: null, glasses: null, neck: null, bg: null },
  avatarBase: { kind: "pixel", index: 0 },          // หรือ { kind: "photo", url: "..." } — รอรอบ D
  coinsToday: 0,          // ใช้กับ dailyCap
  coinsTodayDate: "2026-10-13",  // วันที่ (เขตเวลาเครื่อง server) ที่ coinsToday นับอยู่ — เปลี่ยนวันแล้วรีเซ็ตเป็น 0
  dailyLoginDate: "2026-10-13",  // วันล่าสุดที่ได้โบนัสล็อกอินประจำวันไปแล้ว (กันให้ซ้ำวันเดียวกัน)
  updatedAt: "2026-10-13 10:22",
}
```

**แคตตาล็อกไอเทม**: ไฟล์ static แยกจากข้อมูลผู้เล่น `server/data/shop-items.json`
**ค่าเริ่มต้นชั่วคราว — ต้องมีของฟรี (`price: 0`) อย่างน้อยหมวดละ 1 ชิ้นเสมอ** (5 หมวด: frame/hat/glasses/neck/bg):
```js
[
  { id: "frame_default", category: "frame", name: "กรอบธรรมดา", price: 0, rarity: "default" },
  { id: "hat_default", category: "hat", name: "ไม่ใส่หมวก", price: 0, rarity: "default" },
  { id: "glasses_default", category: "glasses", name: "ไม่ใส่แว่น", price: 0, rarity: "default" },
  { id: "neck_default", category: "neck", name: "ไม่ใส่ของที่คอ", price: 0, rarity: "default" },
  { id: "bg_default", category: "bg", name: "พื้นหลังธรรมดา", price: 0, rarity: "default" },
  // ของซื้อได้ (ราคาชั่วคราวรอสูตรจริง) — ไอคอนจริงมาทำรอบ B
  { id: "frame_sakura", category: "frame", name: "วงดอกซากุระ", price: 150, rarity: "special" },
  { id: "hat_wizard", category: "hat", name: "หมวกพ่อมด", price: 300, rarity: "special" },
]
```
**รูปที่อัปโหลด**: ไม่เก็บไฟล์ในก้อนนี้ เก็บแค่ `url` (รอรอบ D — ตอนนี้ `avatarBase.kind` มีแค่ `"pixel"`)

## 2. Event/API ใหม่ (เพิ่มใน `events.md`)

ทั้งหมดผ่าน Socket.IO ยกเว้นอัปโหลดรูป (HTTP, รอรอบ D):

| event | ทิศทาง | เนื้อหา |
|---|---|---|
| `economy_state` | S→self (ห้องส่วนตัวชื่อ `socket.data.pid`) | ยิงหลังเชื่อมต่อสำเร็จถ้ามี accountId: `{ coins, owned, equipped, avatarBase, catalog }` — Guest ไม่ได้รับ event นี้เลย |
| `buy_item` | C→S (ack) | `{ itemId }` → server เช็คราคา/ยอดเงินเอง ตอบ `{ ok, coins, owned }` หรือ `{ ok:false, error }` |
| `equip_item` | C→S (ack) | `{ category, itemId }` (`itemId: null` = ถอด) → ตอบ `{ ok, equipped }` |
| `set_avatar_base` | C→S (ack) | `{ kind: "pixel", index }` เท่านั้นตอนนี้ (`"photo"` รอรอบ D) |

**error ใหม่**: `INSUFFICIENT_COINS` `ITEM_NOT_FOUND` `ITEM_NOT_OWNED` `ECONOMY_GUEST`

**schema เดิมไม่เปลี่ยน**: `Player.avatar` (0-5 int) คงอยู่ทุกที่เหมือนเดิม — เพิ่มช่อง**ใหม่ไม่บังคับ** `Player.profile: { equipped, avatarBase } | null`
(`null` = Guest หรือยังไม่เคยแต่ง) client เก่า/จุดที่ยังอ่าน `avatar` ตรงๆ ไม่พังเพราะช่องเดิมยังอยู่ใช้เป็น fallback เสมอ

## 3. อัปโหลดรูป (รอบ D — เลื่อนไปทำทีหลัง)

**เก็บที่ไหน**: Firebase Storage ของโปรเจกต์เดียวกับ login (ไม่ใช้ดิสก์ Render — หายตอน restart) server อัปโหลดให้ ไม่ให้ client อัปตรง

**flow**: `POST /api/profile/photo` (multipart, นอก `express.json()` เดิม) → เช็ค session ว่าล็อกอินจริง (Guest ปัดตั้งแต่ตรงนี้)
→ เช็คชนิดไฟล์จากเนื้อไฟล์จริงผ่าน `sharp` (ไม่เชื่อ Content-Type ที่ client ส่ง) → จำกัดไฟล์ดิบ ≤ 2MB → **resize เหลือ 256×256 เสมอด้วย `sharp`** (มีอยู่แล้ว ไม่เพิ่ม lib)

**กันรูปไม่เหมาะสม**: Gemini vision ตัวเดียวกับ `text-check.js` (คีย์ `GEMINI_API_KEY`) **แต่แยกตัวนับโควตาเป็นของตัวเอง** ไม่ใช้ร่วมกับ OCR กันโกง (กันชนโควตากันเอง)
**ตัดสินใจแล้ว**: ไม่มี key/เรียกพัง = **fail-closed ปฏิเสธการอัปโหลด** (ต่างจาก OCR ที่ fail-open) เพราะรูปโปรไฟล์อยู่ถาวรกว่า

**คนอื่นในห้องเห็นรูปยังไง**: ส่งแค่ `url` (Firebase Storage, public read) ไปกับ `profile`/`room_update` ไม่ embed base64 ใน event

## 4. ชั้นของอวตารให้ใช้ได้ทุกที่ (รอบ B)

ขยาย `Avatar.jsx`/`AvatarArt` (จุดเดียวที่ทุกหน้าเรียกอยู่แล้ว — หน้าแรก/ห้องรอ/แถบผู้เล่น/สรุปผล ได้ฟรีทันที):
```jsx
<Avatar index={p.avatar} profile={p.profile} large />
```
ซ้อนชั้นด้วย CSS ใน `theme.css` (ไม่ inline style แบบเดิม): พื้นหลัง → ตัวอวตาร (พิกเซลหรือรูปอัปโหลด) → หมวก/แว่น/ของที่คอ → กรอบ (บนสุด)
`profile` เป็น `null` → fallback ไปใช้ `index` เดิมเป๊ะ ไม่พังของเดิมแม้แต่จุดเดียว

## 5. สูตร coin (ตัวเลขชั่วคราวทั้งหมด — รอสูตรจริงจากอาจารย์)

รวมไว้ที่เดียว `server/economy-rules.json` แก้ทีหลังง่าย ไม่ต้องรีคอมไพล์:
```js
{
  "_note": "ตัวเลขทั้งหมดในไฟล์นี้เป็นค่าชั่วคราว รอสูตรจริงจากอาจารย์ — แก้ตรงนี้ที่เดียวพอ ไม่ต้องแก้โค้ด",
  "guessCorrect": 10,
  "firstGuessBonus": 5,
  "drawerPerGuesser": 3,
  "finishGame": 5,
  "dailyLogin": 20,
  "dailyCap": 200,
  "soloAiGuessCorrect": 2
}
```
(`soloAiGuessCorrect` ≈ ครึ่งหนึ่งของ `drawerPerGuesser` ปัดเป็นเลขกลม — ไม่ได้คำนวณเป็นสูตรลอยตัวจาก `drawerPerGuesser/2` เพราะโจทย์บอกให้ตัวเลขทั้งหมดเป็นค่าคงที่แก้ตรงๆ ได้)

**จุดให้ coin (server ให้เองทั้งหมดเท่านั้น)**:
- ห้องปกติ/ทีม: ทายถูก → ผู้ทาย +`guessCorrect` (คนแรก +`firstGuessBonus` เพิ่ม) · จบตา → คนวาด +`drawerPerGuesser` × จำนวนคนที่ทายถูกในตานั้น · จบเกม (ยังอยู่ในห้องตอนจบ) → ทุกคน +`finishGame`
- **Solo**: **เฉพาะ** ช่วง 1 ("เราวาด AI ทาย") ตอน AI ทายถูก → +`soloAiGuessCorrect` **เท่านั้น** ไม่มีทางอื่นได้ coin ในโหมดนี้
- ล็อกอินเล่นวันนี้เป็นครั้งแรก (เช็คจาก `dailyLoginDate`): +`dailyLogin` (ไม่นับเป็นผลจากการเล่น แต่ยังกิน `dailyCap` ร่วมกัน)

**กันปั๊ม**:
1. **`dailyCap`** ต่อบัญชีต่อวัน — ชน cap แล้วเล่นต่อปกติ แค่ coin ไม่เข้า ไม่ error ไม่บล็อกการเล่น
2. **ห้องปกติ/ทีม ต้องมี ≥ 2 บัญชีจริงไม่ซ้ำกัน** (`accountId` ไม่ใช่ `playerId`) ถึงจะให้ coin จากทายถูก/จบเกม — กัน 1 คนเปิดหลายแท็บ/หลายกุญแจทายกันเองในห้องเดียว
3. ไม่มีทางยิง guess-event ซ้ำได้อยู่แล้ว (กติกาเดิมของเกม) จึงไม่มีช่องให้ coin ซ้ำจากเหตุการณ์เดียวกัน
4. ความถี่ `buy_item`/`equip_item` ผ่าน `rateOk` เดิม (กัน spam event ไม่ใช่กันปั๊ม coin โดยตรง)
5. **ข้อจำกัดที่ยอมรับ**: คนมีหลายบัญชี Google เปิด 2 แท็บเข้าห้องเดียวกันทายกันเองยังปั๊มได้ (ผ่านด่าน "≥2 บัญชีจริง" เพราะนับแค่จำนวนบัญชี ไม่ใช่ตัวตนจริง) — ติด `dailyCap` ต่อบัญชีจำกัดความเสียหายไว้ ไม่ได้แก้เพิ่มในแผนนี้

## 7. ความเสี่ยง (คงเดิมจากที่อนุมัติ + ปรับตามข้อ 1-5 ด้านบน)

1. อัปโหลดรูปเสี่ยงสูงสุด — เลื่อนไปท้ายสุดแล้ว ใช้ fail-closed ตามที่ตัดสินใจ
2. ต้องเพิ่มบริการใหม่ (Firebase Storage) ตอนทำรอบ D — จุดตั้งค่าที่พลาดได้ตอน deploy
3. ของฟรีต้องมีครบทุกหมวดตั้งแต่รอบ A (data) + รอบ B (ไอคอนจริง) ไม่งั้น UI ว่างเปล่า
4. ตัวเลข coin/ราคาเป็นค่าชั่วคราวทั้งหมด ต้องรอสูตรจริงจากอาจารย์มาแทนที่ทีหลัง (บันทึกไว้ในไฟล์ json + ที่นี่แล้ว)
